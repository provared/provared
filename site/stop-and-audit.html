Provared

A hard stop and an audit trail in front of an AI agent's tools

For a business whose AI agents act on real systems: email, customer records, a database. Evidence, not a verdict.

An agent can do what nobody meant it to: a test run that emails real customers, a change to live data. Asking a person to approve every step often does not last: after a few weeks the approvals are clicked without being read. And the log of what happened is usually written by the same software, and can be edited by whoever runs it.

What the guard does

  • Holds the credentials. The guard sits between the agent and one tool server: the program through which the agent uses a system such as email or a database. It holds the tool server's access key in place of the agent.
  • One permission, signed once. A person signs it with a passkey (the fingerprint, face or PIN prompt on a phone or computer). It says which actions the agent may take (the guard's settings say which tool is which action), how many in a period, until when, and for what purpose.
  • A hard stop. The guard checks each call against the permission. A call it does not allow is refused before it reaches the tool, and the guard signs a note of the refusal. By default, a tool you have not listed is not shown to the agent, and a call to it is refused.
  • An audit trail. For each call it lets through, the guard signs a receipt that points back to the permission. The receipts can be sealed, so a later change to one shows when they are checked.
  • Checked by anyone. A security reviewer or an auditor checks the permission, the receipts and the refusals on their own computer, with the free checker.

Where it works

With tools that use the Model Context Protocol (MCP), the common way for AI agents to reach tools. The guard runs on the same computer as the agent, or on a server for several agents, each with its own permission and its own record. A business can run it on its own server and add it to claude.ai as a custom connector; the owner approves each new connection with a passkey. It is the npm package provared-mcp-executor.

What it does not do

  • It covers only calls that go through it. A tool the agent can reach another way, or a step in your own software that is not a tool call, is not covered.
  • It keeps the credential from the agent only where the agent cannot read the guard's files: a separate user account, no shell or file tools for the agent, or the guard run apart from the agent, over the network, where the agent cannot read its files (tried with separate containers on one computer; on separate computers it has not been tried). The home page says more.
  • It knows a call by the tool's name and your rule for it. It does not understand what the tool does.
  • A tool server reached over the network must accept a fixed access key. One that only accepts its own sign-in (OAuth) is not served yet.
  • One guard stands in front of one tool server.
  • Unless a central sealer holds the sealing keys, whoever can read the guard's files can write and seal a record of their own.
  • A record does not show that an action was wise, lawful or wanted.

Cost, data and review

Cost.Free and open source, under the Apache License 2.0. Nothing is sold here. There is no hosted service: you run the guard yourself.

Your data.Nothing is sent to the author (no telemetry). The credentials and the records stay where you run the guard. The guard sends each allowed call on to your tool server and, where you set one up, asks a time-stamp service to date each seal.

Review.Draft software, built by one author with AI tools since 3 October 2026. No person other than the author has reviewed the code yet.

Try it on one tool for a week

  1. See it work in front of a made-up tool, with no passkey and no settings, on a computer with Node.js 24.7 or later: 
    npm install -g provared-mcp-executor
provared-mcp-executor demo
    Its records prove nothing about anyone.
  2. Put it in front of one real tool: the guard's README sets it up in five steps, and the claude.ai recipe adds it to claude.ai. The recipe has been tried only in a test on one computer; an earlier build of the guard itself ran with claude.ai on a server on the internet on 15 November 2026.
