# Gateway choices: its own countersignature, its own copy, and the first publication (21 November 2026)

One line each: the choice; why; the other way.

- **X371 (replaced after review 3.4, H2).** The gateway has a `with` entry of its own, as the guard has: its id is `gateway.id` in the settings (`gateway` if left out), the slip's entry under that id carries the gateway's keys, and every stub of an agent whose slip names it names that id. The upstreams' own entries stay free for the upstreams' real keys. Why: the lead specialist's decision after the review; under the upstream's own entry, the gateway's countersignature read as the upstream's, and shut out the upstream's own. (Was: the gateway's keys in the `with` entry of the upstream's service, and the stub's `with` that service.) See X390 to X393.
- **X372.** The gateway countersigns wherever the slip names its keys for the service, whether or not `requires` asks for it, and warns where the slip does not require it for every action. Why: as the guard does (its DESIGN.md, section 6, "countersigns anyway"). Other: countersign only where a condition asks for it.
- **X373.** For an agent and a service whose slip entry names the gateway's keys, the upstream's `countersign` address is not used, and a warning says so. Why: the upstream's countersignature would not check against the gateway's keys, and a stub carries one countersignature. Other: refuse such settings at start.
- **X374.** The setting is `gateway`, with `keys` (a key file of two keys, Ed25519 then ML-DSA-87), `name` ("Provared gateway" if left out) and, in a program, `privateKeys` with `keySet`; no `signers` module. Why: the guard's own key set is a key file only; the recorder's in-memory form is kept for programs and tests. Other: a signers module, as for the agents.
- **X375.** A copy is kept for every agent whenever `gateway` is set, and for none without it. Why: the copy goes with the gateway's own identity; an agent whose slip names the gateway's keys for no service still gets its calls in the copy, so `compare` shows them. Other: a copy only for agents whose slip names the gateway's keys.
- **X376.** Each agent's copy is at `copy` (default `copies/<agent>.jsonl`, from the settings' folder) and its key at `copyKey` (default the same with `.key`). Why: the guard's defaults over HTTP, where it also has several agents. Other: beside the book, as the journal is (which is where the agent's side is likeliest to reach).
- **X377.** Each copy line's tag is HMAC-SHA-256 under the agent's copy key of the agent's name, a line feed and the line: the guard's copy's layout, with the agent's name where the guard has its own. Why: the gateway has no name of its own today in its journal tags, which use the agent's name; a copy is the agent's. Other: the gateway's `name` (which would make a renamed gateway's copy stop checking).
- **X378 (changed after review 3.4, H1: a copy `sending` line with no receipt is no longer noted `withdrawn`; it waits for the administrator; see X394).** The copy's `sending` line is written before the journal's, and a copy `sending` line with no journal line, no stub and no line setting it aside is noted `withdrawn` (`reason: "not-sent"`) at the next start. Why: the journal's line is on the disk before any call is sent, so its absence shows the call was not sent; written the other way round, a call could reach the book with no `sending` line in the copy. Other: the journal's line first.
- **X379.** A copy key is made only where the copy file is missing or empty. Why: a new key for a copy that holds lines would make every line fail to check, and leave a wrong key on the disk. Other: as the guard, make it and then refuse.
- **X380.** The copy's lines name the upstream (`upstream`, its name in the settings) where the guard's name the tool; no method, path, query, body or answer. Why: the guard's copy holds "names, times, codes and fingerprints", and a path can hold data. Other: the method and the path.
- **X381.** `refused` lines are written for the refusals that write a denial (body too large, no rule, amount not read, not allowed by the check), each with the call's identifier or, before one is made (body too large), a new one. A call answered `401`, `400` or `503` before that, or forwarded with no rule, has no line. Why: these are the calls the stub writer saw; the others write nothing in the book either. Other: a line for every call.
- **X382.** A copy line that cannot be written stops that agent until the next start (`503`, `agent-stopped`, event `copy-not-written`). Before a call is sent, the call is then not sent; after, the agent still gets the upstream's answer. In an acknowledgement, the call leaves the list first, so that trying again writes no stub twice. Why: as the book file that cannot be written. Other: carry on with the copy behind.
- **X383.** `compare` finds a call in the book by its `gateway.call` document under any service, counts as "not in the copy" only receipts under a service the slip gives the gateway's keys for, names its summary field `notWrittenByGateway`, and has none of the guard's parts on rules on content. Why: older receipts under other services, written before the copy was kept, would otherwise never agree; the gateway has no rules on content. Other: all receipts that name `gateway.call`.
- **X384.** A `done` line written on acknowledgement says `outcome: "acknowledged-outcome-unknown"`; one written at a start for a stub the book holds says `found-in-book`. Why: the guard's words; the gateway always writes "outcome not known" on acknowledgement. Other: new words.
- **X385.** `keys --gateway` prints one `with` entry for each service the upstreams name (named "<service>, through <gateway name>") and `"requires": [{"need": "countersignature"}]`, and refuses a path that is the recorder's or an agent's key file. Why: the guard prints the `with` entry and `requires` that the slip takes as they are. Other: the public keys alone.
- **X386.** The gateway refuses to start, and `check` gives a problem, where a slip names the gateway's own keys as the agent's. Why: a countersignature by the agent's own keys adds nothing. Other: a warning.
- **X387.** `package.json` asks for `provared` 0.9.0 exactly, lists `copy.mjs`, `compare.mjs` and `CHANGELOG.md`, exports `./compare`, and stays at 0.1.0. Why: the brief, and the guard's exact pin; 0.1.0 has never been published. Other: keep the range.
- **X388.** `compare` takes the recorder a seal must be signed by from `--sealer`, or else from the recorder's key file in the settings, where it is there. Why: as the guard's `compare`. Other: compare seals with nothing.
- **X389.** The warnings at start go into the log as `{"event": "warning", "agent", "message"}`. Why: the gateway has no other channel for them at start, and `check` prints the same sentences. Other: write them to standard error apart from the log.
